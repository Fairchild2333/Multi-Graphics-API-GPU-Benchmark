# iPad8,1 七项复核与测试设计改进（2026-10-16）

剩余七项已在同一轮真机测试中全部 passed。当前完整选用的 31 项／33 条均通过
生产模型和质量检查。实际运行的是原版 App 四项独立对照及修正版七项复核，
**不是再次点击运行整套 31 项**。原始界面测试的失败状态不改写。

## Vulkan 计时

iOS MoltenVK 纯计算上次已经强制同步，绘制仍依赖启动时的查询校准。现在粒子的
计算／绘制均整轮采用同步提交／栅栏完成耗时，避免正式帧查询异常绕过启动校准。
当前 iOS 粒子合同不再复用旧查询计时记录；旧数据保留。Android／HarmonyOS 原生
Vulkan 和 macOS 桌面选择路径不变。没有新增 API 开关或禁用整种 API。

## CPU 全核验证

全核计分仍为八个线程的实际工作量除以共同墙钟时间，三轮中位数，内核未变。
全核允许线程在大小核之间迁移；它不等于要求每个工作线程都满足单核测试的
99% 核型纯度。原逐线程核型验证仍保留，但新全核质量检查改用实际 CPU 时间：

- 所有轮次中，大核组 CPU 时间至少达到该组容量的 90%。
- 小核组也至少达到该组容量的 90%。
- 每个工作线程的实际占用至少 90%；异常计数、缺少计数或不合理超容量不通过。
- 单独测大核／小核时，原 99% 驻留要求完全保留。

新记录保存 `allCoreValidation=aggregate_cpu_time_v1`、三轮最低组占用和线程
占用，并追加独立版本标记。旧记录没有因此重新判成通过；需要本轮实际新记录。
测试覆盖核型迁移仍充分参与、某组闲置、单线程参与不足和缺少计数等情况。

## Metal 判断及验证范围

未改 Metal 计算内核、固定画面覆盖和 2% 稳定段阈值。原版 App 不带 UI 自动化工具
的独立对照中，1M、16M、CPU 已通过，4M 仍有一次稳定性提示；修正版此轮三档均
通过稳定段检查，早晚下降均不足 1%。这些条件还存在运行顺序、热历史等差异，
不能据此准确量化 Xcode 的开销，也不能断言所有原波动都来自 App。保留全部曲线。

当前选用完整最新轮次，不按最高分挑选。后续若确有波动、计时异常或参与不足，
App 仍会标记 review，不保证每次运行都得到稳定段。新逻辑已接入现有一键流程，
正常使用无需电脑辅助计分。

Release 引擎／签名 App 构建、CPU 驻留与取消检查、Swift 合同正反例检查均通过。
