# 砺算 LX 7G100 测试记录（2026-10-20）

这台电脑（9800X3D）把 RTX 5090 换成了砺算 LX 7G100，在 Windows 上测了完整测试里这张卡的
46 项。第一轮暴露出驱动和引擎各自的问题；引擎的三处已修，受影响的 15 项用修好的引擎重测，
显存测试为这张卡临时改了一次着色器（测完已还原）。原始日志、这张卡的全部 55 条记录和
已知错误清单在 [out/test-results/lx-7g100-20261020](../out/test-results/lx-7g100-20261020/)，
测试时的状态见其中的 [DEVICE-STATE.txt](../out/test-results/lx-7g100-20261020/DEVICE-STATE.txt)。

## 显卡

公开规格：12 GB GDDR6、192 位、**432 GB/s**，FP32 标称 24.6 TFLOPS（若双发射用不上则为 12.3），
225 W，PCIe 4.0 x16。驱动 30.0.2260.773；DX11 为 11_1 特性级别；OpenGL 报告
“4.6 Core Profile Mesa 22.0.4”。引擎读到 11,821 MB 显存。

## 第一轮的问题与处理

第一轮（`--fill-missing`，只跑这张卡缺的 46 项，核显、WARP、CPU 不重测）：
23 项可信，7 项存进了错误分数，8 项只存了 0 分，8 项没有成绩（OpenGL 窗口 7 项崩溃，Vulkan 显存 1 项作废）。

### 引擎的三处（已修）

1. **GPU Burn 的计时不做合理性检查。** 这个驱动在 DX12 下给的 GPU 时间约 0.006 ms，
   而一帧实际 9 ms（GPU 利用率 0.1%）；DX11 约为帧时间的 1%。引擎照样算出 4,689–72,418
   和 1,152–1,291 并存为成绩。现在 GPU Burn 预热期间若 GPU 时间不到帧时间的 5%
   （V-Sync 关闭时 GPU Burn 不可能这样），改为墙钟计时（`src/app_base.cpp`）。
   DX12 原来没有墙钟计时，补上了：单 GPU 的 headless 和只有片元着色的帧，用一个围栏等待计时
   （`src/dx12_backend.cpp`）。核显上同样的测试不触发（DX12、DX11 的 Burn 64 仍为 1.29）。
2. **DX11 改用墙钟后一帧也没计上。** 这个驱动的 `D3D11_QUERY_EVENT` 查询返回成功
   但始终不报完成，等待函数直接放弃，于是 0 个样本、0 分。现在遇到这种情况，
   改为映射一次暂存缓冲的拷贝来等 GPU（`src/dx11_backend.cpp`）。
3. **OpenGL 粒子 16M 一次派发超出驱动上限。** 16,777,216 个粒子要 65,536 个工作组，
   这个驱动只允许 65,535（OpenGL 规范保证的最小值），整次派发什么都没做，算出 1,520,641 GB/s。
   和 10-17 修树莓派 Vulkan 时一样，改为对缓冲区的不同部分分几次派发
   （`src/opengl_backend.cpp`）；限值足够的驱动命令不变。

### 驱动的问题（本项目修不了，已绕开或记录）

- **OpenGL 窗口模式崩溃。** 在 `LSOGLICD_64.dll` 内部，异常 0xc0000409，偏移 0x507ec5，
  每次相同；不开 RenderDoc、开 V-Sync、换像素格式（无深度/无 alpha、sRGB、兼容配置）都一样。
  逐步打印确认崩在第一帧的 `SwapBuffers`，之前的绘制都正常。改用单缓冲窗口时帧能跑完
  （Burn 64 每帧 6.12 ms，和 Vulkan 的 6.08 ms 一致），但收尾时仍崩，而且单缓冲不是正式的窗口模式，
  所以 OpenGL 窗口 7 项（粒子 4 项、Burn 3 项）这张卡没有成绩。
- **Vulkan 显存测试的读取极慢。** 读取内核把源缓冲声明为 `volatile`，这个驱动遇到 volatile
  读会走一条慢路径：2 GiB 只有 5.9 GB/s，去掉后 296.7 GB/s，差五十倍（写入同样带 volatile，不受影响）。
  另外，显存测试最后测“GPU 读写系统内存”的那段，在 8 MiB 得到 462 GB/s（PCIe 4.0 x16 最多约 32），
  计时检查不通过，整次测试作废。所以标准版本在这张卡上测不出显存成绩；上面的 296.0 来自临时版本，
  见下一节。
- **GPU Burn 的帧时间会整倍翻倍。** DX11 64 步在 5.4 ms 和 10.6 ms 之间来回跳，DX12 256 步在
  24.9 和 49.7 ms 之间，第一次 Vulkan 256 步也有几秒是 44.9 ms（正常 22.45）。看起来是 GPU 在两档速度
  之间切换。重跑的 Vulkan 256 步全程稳定（21.02，波动 0%）；DX12 256、DX11 64/256 重跑仍没稳定，
  记录里是含慢段的全程平均。按帧时间短的那段算，DX11 64 / 256 约 21.9 / 24.1，DX12 256 约 19.0。
- **3DMark 认不出这张卡的 Vulkan。** Steel Nomad 选 Vulkan、Wild Life Extreme（在 Windows 上只用 Vulkan）
  都报 “Vulkan API not supported”。用 `vulkaninfo` 看，驱动给的设备编号是空的：`deviceLUID = 00000000-00000000`
  却标为有效，deviceUUID 为 `00000000-0100-…`，driverUUID 是 ASCII 的 “vendor_vk_mesa_d”，driverID 是没登记的值
  （0x7FFFFFFE），driverInfo 写着 “Mesa VK driver 1.3.0”。DXGI 里有三个名为 LX 7G100 的适配器，LUID 分别为
  `00019789`（接着两个显示器）、`0002c674`、`00029e53`（后两个没有输出，来历不明），3DMark 的“渲染设备”列表里也是三个；
  没有一个和 Vulkan 报的 0 对得上。核显的 Vulkan LUID（`00019dc2`）和 DXGI 一致，3DMark 能认。所以 3DMark 选中
  LX 7G100 后多半找不到 LUID 相同的 Vulkan 设备（它的判断方法没公开，这一点是推断）。本项目的引擎在 Vulkan 自己的
  设备列表里选卡，不靠 LUID，所以不受影响。另外，加载器提示 `LSVKICD_64.dll` 声称支持 Vulkan 1.3，却只实现了
  加载器接口版本 4（1.1 以上要求版本 5）；功能列表本身是完整的 1.3（dynamicRendering、synchronization2 等都有）。
  在 3DMark 里可以选 DX12 跑 Steel Nomad；Wild Life Extreme 的标准测试在 Windows 上固定用 Vulkan，
  它的自定义运行里有 DX12 选项，能否运行还没试。读出的原始信息在存档的 `3dmark-vulkan/` 里。
- **VRMark 的 Orange Room 和 Blue Room 跑一会儿就闪退，Cyan Room 正常。** 用户看到闪退瞬间窗口里有方格闪烁，
  VRMark 报 `IDXGISwapChain::Present failed [-2005270523]`，即 0x887A0005（DXGI_ERROR_DEVICE_REMOVED）。
  系统日志里同一天 12:05、12:07、12:12、12:57 各有一次显卡超时重置（Windows 错误报告 `LiveKernelEvent 141`，
  故障桶 `LKD_0x141_Tdr:6_IMAGE_LSGKMD.sys`，`LSGKMD.sys` 是砺算的内核态驱动），12:02 刚装过 VRMark 的
  SystemInfo 组件，时间对得上。Orange 和 Blue 用 DirectX 11，Cyan 用 DirectX 12，所以看起来是 DX11 驱动在
  较重、较长的负载下卡死，被 Windows 重置。本项目的 DX11 测试每项 15 秒、负载较轻，没有触发。
  内核转储在 `C:\Windows\LiveKernelReports\WATCHDOG`，需要管理员权限，没有读。
- **系统 HDR 打不开。** 用户观察：显示器支持 HDR，换上这张卡后 Windows 里打不开。卡拆下之前没来得及读
  显示器的高级色彩状态，原因没有查。

## 记录里的错误条目（按要求没有删）

7 条错误分数（DX12 Burn 3 条、DX11 Burn 3 条、OpenGL 16M headless 1 条）和 8 条 DX11 粒子的 0 分记录，
都还在 `%LOCALAPPDATA%\GpuComputeBenchmark\results\results.json` 里，每项都有一条更晚、
用修好的引擎测的记录取代它。编号和原因见
[KNOWN-WRONG-ENTRIES.txt](../out/test-results/lx-7g100-20261020/KNOWN-WRONG-ENTRIES.txt)。
完整测试的状态文件里，DX11 粒子 8 项仍记为“失败”，Vulkan 显存和 OpenGL 窗口 7 项也是，
“补齐缺失”不会自动重跑它们（DX11 粒子已有重测的成绩；显存有临时版本的成绩，但版本名不同，
完整测试不把它算作标准显存成绩）。

## 临时显存测试（已还原）

只为这张卡做：读和复制内核去掉 `volatile`，跳过“GPU 读写系统内存”那段，版本名改成
`membw_v3_streaming_lx7g100_nonvolatile_temp`，用一份临时编译的副本测了两次：第一次（读 295.8）存进
[单独的 results.json](../out/test-results/lx-7g100-20261020/membw-nonvolatile-temp/results/results.json)，
第二次（读 296.0，`20261020-030605-785-membw`）按要求存进 PC 记录，带着这个版本名，不会和标准版本混在一起。
源码随即还原，正式引擎重新编译，仓库里的着色器和引擎都没有这项改动。
