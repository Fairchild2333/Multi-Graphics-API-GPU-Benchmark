- 11 个 task_struct 候选已从本镜像机器码取得：prio=0x84、normal_prio=0x8c、sched_task_group=0x310、pi_lock=0x86c、pi_waiters=0x880、pi_top_task=0x890、pi_blocked_on=0x898、real_cred=0x778、cred=0x780、comm=0x790、seccomp=0x848。pid/tgid/tasks/atomic_flags 尚未推导。
- cred 拷贝大小候选为 0xa8（168），由 cred_init 和 prepare_creds 两处指令一致确认；非零 capability 槽在 0x30/0x38/0x40；引用在 0x80/0x88/0x90。
- remove_waiter 有上游关注的未修复静态特征，但这不是端到端提权成功证明。
- multicast_waiter：复制窗口 264 字节，waiter 起点相对窗口为 416；要覆盖 lock 末端需要 480 字节。内核明确校验 264，单纯增大配置无效。
- select_stack：实际 task/lock 位于输入窗口的第 16/17 个 8 字节字；当前 NFDS=320 的三组输入只覆盖第 0..14 个字。增大到下一档会进入堆分配，不能直接修正。
- tcp_zerocopy：目标旧 ABI 最多复制 24 字节；当前上游载荷的关键字段在 40/48 字节，复制不到。

候选结构字段没有经过真机或原始调试类型的最终验证。不要把其他机型的偏移当作已验证参数。也不要把原始 select 窗口差值直接写成 profile shift，运行时编码另有偏置。

## 替代路径核验（2026-10-11 晚间已完成）

原先暂停时留下的 6 个函数反汇编已全部分析完，结论与证据见 `MP6-kernel-analysis\MP6-alt-route-audit.md` / `alt-route-audit.json`，复核脚本 `replay_alt_route_audit.py`（本次 exit 0；旧三条路径仍用 `replay_static_audit.py`，本次重跑亦通过）。要点：

- ppoll/do_sys_poll：stack poll_list 首块 ≤240B 在深度 1044，需要 660B 才够到深度 384..400，溢出块走 kmalloc。**排除。**
- rt_sigreturn 自身 24B 拷贝与 restore_sigframe 的 GPR 直写 pt_regs：无栈窗口。**排除。**
- **restore_fpsimd_context：缓冲低端深度 768、vregs 512B 可控，waiter 落在 vregs[20..24)，task/lock=vregs[23]（帧记录内偏移 0x180/0x188）；盖章是整个 syscall 最后一次深栈写，parse_user_sigframe 全函数无调用、复制后无破坏。几何与结构可行。**
- restore_sve_fpsimd_context：同构（waiter_offset=336、task/lock=vregs[24]），需 ARM64_SVE cap，作备选。
- 帧构造硬要求已定（16 对齐、access_ok 0x1250、magic 0x46508001、size 精确 0x210、记录链 @ sf+0x250、END{0,0}、pstate 过 valid_user_regs、sigmask 全阻塞）；校验失败会被杀进程。
- cpu_hwcaps 位映射已定源：bit4=ARM64_HAS_PAN、bit0x10=ARM64_HAS_NO_FPSIMD（SM8450 上为 0，fpsimd 路径生效）、bit0x16=ARM64_SVE。来源 AOSP android12-5.10 cpucaps.h。
