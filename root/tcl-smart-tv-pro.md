# TCL 电视（Smart TV Pro，MT5889）—— Root 调研（2026-11-06）

## 本仓库档案

`HANDOFF.md` 2026-10-08 第十六台设备：

- `Smart TV Pro`（代号 **G05**），联发科 **MT5889**，4 × Cortex-A73 **恒 1300 MHz**（上限即此值，
  跑 CPU 测试读到的也是它），Mali-G52（驱动 r25p1），**Android 11，系统整体 32 位（armeabi-v7a）**，
  2.7 GiB 内存，界面 1920×1080。
- 网络调试：`adb connect <IP>:5555`（2026-10 时为 192.168.20.15，遥控器点允许）。
- 成绩副本 `out\adb\TCL-Smart-TV-Pro-20261008-175614\results.json`（47 条）；
  2026-10-17 又测显存带宽一次（256 MiB 堆）。
- 无电池、温度报固定 42.4 °C（传感器不可用）。
- **空闲时自有服务占 400% 里约 40%**，还会自行更新应用编译占核——「接电视先看 top」。

## 位数结论（2026-11-06 确认）

**芯片不是 32 位的，是系统选了 32 位：**

- Cortex-A73 是 ARMv8 核心，硬件原生支持 AArch64，不存在 32 位版 A73。
- 32 位的是软件栈：用户空间全部 `armeabi-v7a`（引擎也是编 32 位包给它）。
- 旁证：机队里小米显示器（MT9655）用**同款 A73**跑 64 位系统，每 MHz 的 CPU 成绩是这台的
  2.6 倍（64 位整数运算主导的测试）——同核心，差在系统位数。`_32bit` 组不能和 64 位组直接比。

**内核位数待验证**（公开 payload 是 arm64 还是能用，就看这条）：

```
adb shell uname -m        # aarch64 = 64位内核+32位用户空间；armv7l/armv8l = 内核也是32位
adb shell uname -r
adb shell getprop ro.build.version.security_patch
```

## Root 可行性

| 内核位数 | 结论 |
|---|---|
| `aarch64` | **架构墙不存在**——arm64 公开 GhostLock/DirtyFrag payload 架构适用，剩下的只是 MT5889 无先例的偏移移植工作量（与小米显示器同级：没轮子，但能造） |
| `armv7l` / `armv8l` | **架构墙**——公开 payload 全部 AArch64，需从零移植 arm32 版，MTK 电视平台零先例，放弃 |

- 理论漏洞面：Android 11 电视内核大概率 4.9/4.19，电视基本不推安全补丁，
  GhostLock（2.6.39+）/DirtyFrag（4.19 时）/范围内核未修复概率极高。
- MT5889 是**电视 SoC**，与手机 MTK 完全两码事：无 mtkclient BROM 通道、无固件公开下载。
- BL：无官方解锁，无社区方案。

## Root 的预期收益（如实评估）

- **CPU 锁频没有需求**：这台 CPU 恒 1300 MHz（上限），不存在降频波动。
- **冻结后台有需求**：空闲 40% 占用 + 自更新编译是它成绩的最大干扰源；root 冻结比锁频更对症。
- Mali-G52 频率波动情况未测：先用无 root 方式跑分采样 `devfreq/*/cur_freq`（读不需要 root），
  有波动再考虑投入移植。

## 建议

优先级低于小米显示器（G Pro 27U）：那台是 arm64 + Android 14 + 后台占一个核，
收益更大。这台先把 `uname -m` 跑了——结果是 `armv7l/v8l` 就彻底关掉这个念头，
是 `aarch64` 再评估值不值得为「冻结后台 + 锁 GPU 频率」投入一次移植。
