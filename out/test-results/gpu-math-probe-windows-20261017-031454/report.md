# Windows GPU 数学探针与 M4 Pro 对比：2026-10-17

把 Metal 数学探针（`scripts/metal-math-probe`）按同样的内核写成 D3D11 计算着色器
（`scripts/gpu-math-probe-windows`），在本机 RTX 5090 和 9800X3D 核显上各跑一次，
与 M4 Pro 2026-10-16 的 fast 模式结果对比。目的是判断：苹果 GPU 的 GPU Burn
每 TFLOPS 偏低，能否用特殊函数相对 FMA 的速度来解释。

没有改引擎、着色器、测试代码或已有文件，没有重跑任何已有成绩。GPU Burn 256 的
分数取自 [docs/interpreting-gpu-burn.md](../../../docs/interpreting-gpu-burn.md)
的表，M4 Pro 探针数据取自
[metal-math-probe-20261016-233740/output.txt](../metal-math-probe-20261016-233740/output.txt)。

## 条件

- 主机：Ryzen 7 9800X3D，Windows 11 Pro 10.0.26300。RTX 5090 驱动 32.0.16.1692，
  核显驱动 32.0.21045.5002。DXGI 序号：0 = RTX 5090，1 = 核显
  （2、3 也是 5090，来自两个虚拟显示器驱动，跳过）。
- 着色器用 `D3DCompile`、`cs_5_0`、flags 0 编译，与引擎 DX11/DX12 编译 GPU Burn
  相同（默认优化、无 IEEE 严格）。D3D 没有精确模式，所以只有一张表，对应 Metal 的 fast。
- 5090 运行中 SM 频率 2.70–2.86 GHz（约 2.78），功耗最高 538 W（上限 575 W），
  见 `nvidia-smi-during-run.csv`。核显没有频率读数。
- 先 1 秒 FMA 预热再开始计表。表后复测 FMA：5090 为首行的 0.979，核显 0.999，
  运行中速度稳定。
- 正式运行前用户停了视频，此时 5090 只有桌面合成约 3% 占用，核显无占用。
  之前在草稿目录试跑过 3 次 5090（其中 2 次可能在放视频），FMA 为
  34.9–35.6 T 次/秒，正式 37.0，差 6% 以内；试跑未存档。

## 1. 各函数相对 FMA 的速度

"vs fma" = 该函数每秒结果数 ÷ 同一 GPU 上 FMA 内核每秒结果数。5090 另列一栏
"对字面常数 FMA"，原因见下。

| 函数 | M4 Pro（Metal fast） | RTX 5090 | RTX 5090 对字面常数 FMA | 核显 |
|---|---:|---:|---:|---:|
| FMA 内核 FP32 TFLOPS | 6.96 | 73.93 | 98.51 | 0.667 |
| sin | 0.122 | 0.187 | 0.140 | 0.238 |
| cos | 0.123 | 0.188 | 0.141 | 0.237 |
| atan2 | 0.067 | 0.057 | 0.043 | 0.040 |
| exp | 0.288 | 0.190 | 0.142 | 0.237 |
| pow | 0.140 | 0.096 | 0.072 | 0.122 |
| sqrt | 0.287 | 0.183 | 0.137 | 0.236 |
| division | 0.288 | 0.187 | 0.140 | 0.238 |
| Burn 单步 Gpix-step/s | 14.644 | 205.968 | 205.968 | 1.622 |

**FMA 分母的问题。** 与 Metal 版相同的 FMA 内核从常量缓冲区读 `a`、`b`。
在 5090 上它只有 73.93 TFLOPS；把 `a`、`b` 写成字面常数（值相同）后为 98.51，
快 1.33 倍。按运行中约 2.78 GHz 算，5090 FP32 峰值约 121 TFLOPS：字面常数版为
81%，与循环开销（每次迭代 16 条 FMA + 约 3 条计数/跳转）的上限 84% 相符；
常量缓冲区版只有 61%，原因没有查明（看不到 NVIDIA 的机器码）。核显两种写法
一样快（0.994）。M4 Pro 只测过常量缓冲区版，6.96 是否是它的 FMA 峰值：不确定。

**硬件上的解释（推算，未直接验证）：**
- 5090 的 sin 为 6.92 T/s，约为特殊函数单元峰值（每 SM 每周期 16 个，
  170 SM × 2.78 GHz = 7.56 T/s）的 91%，即跑满了。对峰值 FMA 约为 1/8。
- 核显 sin、cos、exp、sqrt、除法五个内核速度几乎相同（78.6–79.3 G/s），
  约为 FMA 的 1/4，说明瓶颈是 1/4 速率的超越函数单元，其余运算与之重叠。
- 核显 FMA 0.667 TFLOPS 高于按 2 CU、2.2 GHz 算的 0.56；若每周期 128 条 FMA，
  对应约 2.6 GHz。实际频率不确定。
- D3D 编译器（FXC）把 atan2 展开成 1 次倒数加约 20 条普通运算的多项式，
  所以 atan2 主要吃 FMA 单元，不是特殊函数单元（见 `dxbc/k_atan2.dxbc.txt`）。

**各函数逐项看：**
- 只有 sin/cos 在 M4 Pro 上相对更慢：0.122，5090 为 0.187（对字面常数 FMA 为
  0.140），核显 0.238。
- exp、sqrt、除法、pow、atan2 在 M4 Pro 上相对 FMA 反而最快或持平。

## 2. 一个 Burn 单步折合多少次 FMA

用"FMA 每秒次数 ÷ Burn 单步每秒次数"得到每步的耗时相当于多少次 FMA。
这个数不受频率和 GPU 大小影响，只反映这段循环在该 GPU 上的效率。

| GPU | 每步 ≈ FMA 内核次数 | 每步 ≈ 字面常数 FMA 次数 |
|---|---:|---:|
| M4 Pro | 237.8 | 未测 |
| RTX 5090 | 179.5 | 239.1 |
| 核显 | 205.6 | 204.4 |

D3D 路径下每步（DXBC 按分量数）有 23 个特殊运算（sin/cos 12、exp 2、log 1、
sqrt 2、除法 6）和 186 个其他运算；rotate2 的 3 个 sincos 被 FXC 提到了循环外。
按接近峰值的 FMA 计，5090（字面常数）每步约 239 次、核显约 205 次 FMA 的时间，
与 209 个运算的条数相近，而单算特殊函数单元就要约 184 次（5090，1/8 速率）
或 92 次（核显，1/4 速率）FMA 的时间。说明在这两块 GPU 上特殊函数基本与其他
运算并行，时间大多被掩盖了。Metal 编译出的指令数没看到，
M4 Pro 是否同样重叠：不确定。

## 3. 每 TFLOPS（实测）的 GPU Burn 256 分数

TFLOPS 用各自的 FMA 内核实测值；5090 另列字面常数 FMA 的结果。
"真实 Burn ÷ 探针单步"表示真实 GPU Burn（片元着色器、每帧两遍、循环后还有着色）
达到计算内核循环速度的几成。

| GPU | API | Burn 256 | 每实测 TFLOPS | 每字面常数 FMA TFLOPS | 真实 Burn ÷ 探针单步 |
|---|---|---:|---:|---:|---:|
| RTX 5090 | Vulkan | 198.8 | 2.69 | 2.02 | 0.965 |
| RTX 5090 | DX12 | 224.1 | 3.03 | 2.28 | 1.088 |
| 核显 | Vulkan | 1.113 | 1.67 | 1.68 | 0.686 |
| 核显 | DX11 | 1.396 | 2.09 | 2.11 | 0.861 |
| M4 Pro | Metal | 9.66 | 1.39 | 未测 | 0.660 |

文档原表用厂商标称或估计的 TFLOPS（5090 104.8、核显 0.56、M4 Pro 约 9），
M4 Pro 为 1.1、其他 1.9–2.5，即"约一半"。按实测 FMA，M4 Pro 升到 1.39
（因为实测 6.96 低于估计的 9），为其他组合的 0.46–0.83 倍：对 5090 DX12 0.46、
5090 Vulkan 0.52、核显 DX11 0.66、核显 Vulkan 0.83；按 5090 字面常数 FMA 为
0.61（DX12）和 0.69（Vulkan）。

## 4. 差距拆成两部分

差距 =（探针单步每 TFLOPS 之比）×（真实 Burn ÷ 探针单步之比）。
前一项只含计算内核里的数学运算，特殊函数的影响全在这里；后一项是同一 GPU 上
真实 GPU Burn 相对计算循环的损失。

| 对比对象 | 每 TFLOPS 差距 | 计算循环部分 | 真实 Burn 相对循环部分 |
|---|---:|---:|---:|
| 5090 DX12 | 2.19 | 1.32 | 1.65 |
| 5090 Vulkan | 1.94 | 1.32 | 1.46 |
| 5090 DX12（字面常数 FMA） | 1.64 | 0.99 | 1.65 |
| 5090 Vulkan（字面常数 FMA） | 1.46 | 0.99 | 1.46 |
| 核显 DX11 | 1.51 | 1.16 | 1.30 |
| 核显 Vulkan | 1.20 | 1.16 | 1.04 |

## 5. 结论

1. **特殊函数相对 FMA 的速度只能解释一部分，对 5090 来说不是主要部分。**
   在只有数学运算的计算循环里，M4 Pro 每步比核显多花 16% 的 FMA 时间，比 5090
   多 32%（同一 FMA 内核）或一样多（字面常数 FMA）。逐项看，只有 sin/cos 在
   M4 Pro 上相对更慢，exp、sqrt、除法、pow、atan2 都相对更快。
2. **更大的一块在计算循环之外。** M4 Pro 的真实 GPU Burn 只达到自身计算循环的
   66%，5090 为 97%（Vulkan）和 109%（DX12），核显为 86%（DX11）和 69%（Vulkan）。
   对 5090 和核显 DX11，这一项（1.30–1.65 倍）大于计算循环那一项（1.16–1.32 倍）。
   原因不确定。可能的方向（都没测过）：片元着色器在苹果 GPU 上的占用率或寄存器
   压力（循环后的 plasmaNormal 要再算 6 次 plasmaField）、苹果的分块渲染遍、
   每帧两遍。核显 Vulkan 也只有 69%，说明这一损失不是苹果独有，Vulkan 与 DX11
   的差别可能来自编译路径（同一块核显 Vulkan 比 DX11 低 20%）。
3. **M4 Pro 的 FMA 内核是否已到峰值：不确定。** 5090 上同一内核比字面常数版慢
   25%；如果 M4 Pro 也有类似损失，它的实测 TFLOPS 会变大，每 TFLOPS 分数和
   "vs fma" 比值都会变小，计算循环部分的差距会变大。需要在 Mac 上补测字面常数 FMA。
4. **"每 TFLOPS 约一半"取决于用哪个 TFLOPS。** 按实测 FMA，M4 Pro 是其他 GPU 的
   0.46–0.83 倍，只有对 5090 且用同一 FMA 内核时接近一半。

## 6. 限制

- 编译器不同：Windows 探针走 FXC + 驱动，M4 Pro 走 Metal 编译器；
  真实 GPU Burn 的 Vulkan 版走 SPIR-V，与 D3D 探针不是同一编译路径，
  所以 Vulkan 行的"真实 Burn ÷ 探针单步"里混有编译差异。
- M4 Pro 数据是 2026-10-16 在 Mac 上测的，本次没有重测；GPU Burn 256 分数均为
  此前成绩，也没有重测。
- 核显没有频率读数；5090 常量缓冲区 FMA 慢的原因未查明。
- 试跑时还试过一个每次迭代 8 条链各算两次的 FMA 变体，反而只有 FMA 内核的
  0.66 倍，原因未查；没有用于任何结论。

## 7. 建议的下一步

- Mac 上：在 Metal 探针里加同样的字面常数 FMA 行再跑一次（不到一分钟），
  确定 6.96 TFLOPS 是不是 M4 Pro 的 FMA 峰值。这决定第 4 节的计算循环部分。
- Mac 上：把探针的 Burn 单步改成片元着色器，或在计算内核里加上循环后的着色，
  分辨 66% 的损失来自片元路径还是循环后的工作。
- 可选：Windows 上做一个 Vulkan 版探针，分开编译路径的影响。
