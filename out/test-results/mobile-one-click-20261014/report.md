# 安卓／鸿蒙一键全套改进（2026-10-14）

当前已有代码和文档先提交为 **5d4dbc4**。随后完成安卓和鸿蒙应用内三个入口：GPU 全套、CPU 全套、全部项目；这部分保留为新的未提交改动，未推送远端。

| 范围 | 内容 |
| --- | --- |
| GPU 全套 | 依设备能力运行 Vulkan、ES 3.1、ES 2.0 的粒子、GPU Burn、流体和 GPU 内存项目 |
| CPU 全套 | 单核与全核算力，再测缓存/内存曲线、页面映射和存储 |
| 全部项目 | GPU 队列 + 两个 CPU 阶段，CPU 只测一次 |

最多 29 项，缺失 API、流体纹理能力或超出驱动缓冲／计算组限制的项目会省略。正式算力步骤为 15 秒。每项核对新保存的结果，不能用旧成绩冒充本次完成。计时异常、吞吐下降超过 5% 或重负载未达稳定阶段会标记待复核，并继续后续项目。

成绩继续追加到原 results/results.json；每轮计划、成绩编号和完整日志保存在 suite-runs/<编号>。原单项测试与 adb/hdc 脚本保留，调试包可请求 gpu_suite、cpu_suite、all_suite 和 suite_stop。CPU 结果页面同时保留算力汇总和内存曲线。

取消检查发现并修复了共享引擎的问题：CPU 算力和内存循环原先未响应 RequestStop。现在算力能响应取消，内存等当前采样结束后退出；被中断的项目不保存成绩。停止全套也会取消后续队列，等待休息／创建画面时停止不会再启动新项目。切到后台会取消全套。

手机项目间固定休息 30 秒。安卓支持查询系统热状态时还会等待报告正常，最多 600 秒，并记录未知值；鸿蒙当前仅固定等待，日志明确不代表温度正常。安卓热状态接口依据 [Android PowerManager 官方文档](https://developer.android.com/reference/android/os/PowerManager#getCurrentThermalStatus())。真实频率与系统状态仍可能变化。

## 安装 Android Studio／DevEco 后的实际验证

- Android Studio 自动更新的 AGP 9.4.1、Gradle 9.6.0 和 JVM 配置保留；四 ABI APK 构建通过，强制重跑 JUnit 为 4/4 通过。
- DevEco Studio 26.0：修复队列调用私有日志解析函数的编译错误，改用公开批量接口；状态机检查现在也直接使用生产日志解析器验证 CPU 进度和跨阶段汇总。
- 修复鸿蒙资源打包时机：CMake 的 clean 会删除生成的 SPIR-V，原先资源打包早于原生 shader 生成，首包漏文件。现在独立 Hvigor 任务在 clean 后、PreBuild 前准备着色器。移走旧生成目录再 clean 构建，包内验证为 39 个 SPIR-V + 7 个 GLES 源文件，两 ABI 均成功。新增 Mac 构建脚本 scripts/build-ohos.sh。
- 鸿蒙 GPU 操作区改为纵向排列，避免运行状态和停止按钮挤出屏幕；最终模拟器布局验证按钮均在视口内。
- 安卓 35 模拟器：GPU 队列 23 项，两项完成（1 成功、1 待复核），休息期取消后停止；全部项目队列 25 项，首项完成并因吞吐下降标为待复核，随后取消。CPU 算力取消无不完整成绩。清单和日志已拉回 android-studio-suites。
- 鸿蒙 5.0.4 API 16 Mac 模拟器：不提供 Vulkan/ES 3.1，只选 ES 2.0 GPU Burn 16/64/256，3/3 完成、0 失败、2 待复核。所有三项原生成绩保存成功；CPU 队列取消也生效。实际点击“全部项目”生成 5 项，首项完成后在休息期取消，SUITE_END 确认无下一项启动。
- 模拟器由宿主渲染（鸿蒙日志含 Metal 转译，安卓使用 SwiftShader）；上述分数不用于手机或 Mac 正式性能比较。鸿蒙当前系统拒绝 hdc 读取私有成绩目录，流程证据来自引擎保存日志、队列日志和界面状态；没有声称已导出鸿蒙原始 result 文件。
