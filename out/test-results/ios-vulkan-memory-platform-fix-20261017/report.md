# iOS Vulkan 内存平台修复与真机验收 · 2026-10-17

**固定256 MiB上限已修复；12.9英寸A12X iPad8,7实际确认读取平台56.657 GB/s，
83点、38次数据校验通过，App状态passed。**没有降低平台判定门槛或改写旧成绩。

## 原因与实现

原iOS入口把Vulkan扫描上限写死为256 MiB。V3要求三个最大工作集均≥256 MiB，
但旧尾部为128/192/256 MiB，前两个仍是缓存探测布局，因此永远不能满足此条件。
共享Vulkan分配器原来只在Linux系读取可用内存，iOS没有接入App的实时余量。

- iOS默认目标改为**512 MiB**，尾部为256/384/512 MiB；不新增GUI开关。
- 分配前调用`os_proc_available_memory()`，两块大缓冲每块最多使用App剩余分配
  余量的四分之一，同时受Vulkan存储缓冲范围、单次分配和堆预算约束。
- API未提供余量时保守回到旧256 MiB；分配失败继续缩小。预算不足或曲线不平
  仍保留review，不用更小的缓存点冒充内存平台。
- 原完整数据集有序遍历、写入/复制校验、MoltenVK整轮同步计时、三个尾部点
  使用相同方法及最大/最小≤1.2的标准均保持不变。
- 新记录带`_ios_preview_app_budget_v1`及`memoryBudgetPolicy`，保存请求/实际上限、
  App余量快照和单缓冲预算。一键计划拒绝复用旧固定上限版本及缺失预算策略的记录。
- 所有iOS成绩继续保留`ios_preview`平台分组命名，避免与桌面混排；这个后缀
  不等于“未达到平台”。是否达到平台看实际标记和质量状态，本次均通过。

Apple说明该API给出的是当前App的剩余分配额度，属于实时建议值，并非设备空闲
物理RAM；因此不缓存跨运行的余量，也不尝试用满额度。
见[Apple API说明](https://developer.apple.com/documentation/os/os_proc_available_memory)。

设备：iPad8,7，A12X，iPadOS26.7.1，用户解锁后运行新签名Release App。
使用现有App项目`vulkan/memory_sweep`，无自定义扫描参数；测量61.6秒，热状态0→0。

这仍是该内核在统一内存上的访问平台，不是硬件流量计数、绝对DRAM峰值或
已独立归属的GPU L2/L3/SLC测量。
